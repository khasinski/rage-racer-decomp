## Allocation diagnostic

`tools/scripts/alloc_diff.py` compares two candidate compilations. It:

- compiles both with GCC 2.6.3 `-dl -dg` dumps;
- selects only the requested function from multi-function dumps;
- reconstructs `reg_may_share` allocno groups;
- recomputes and verifies GCC allocation priority, including multiword size;
- reports allocation order, hard-register/stack coloring, frame shape, COFF
  local names, and linked retail `exact`;
- optionally preserves the `.s`, `.lreg`, and `.greg` evidence.

It deliberately does **not** claim to recover retail pseudos, priorities, or
allocation order from final machine code. Those compiler-time facts are absent
from the retail executable, so the supported comparison is
candidate-versus-candidate only.

Example for this function:

```sh
tools/scripts/alloc_diff.py func_8003F9C4 \
  scratch/decomp-work/func_8003F9C4/candidate-codex3-integer-step-record.c \
  scratch/decomp-work/func_8003F9C4/candidate-codex3-split-pos-increment.c
```

That comparison reports `exact 13 -> 0`, an unchanged retail-sized frame, and
the relevant allocation/coloring changes.
